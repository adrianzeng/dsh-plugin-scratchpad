# 投递契约

本插件唯一会写到「库根」之外的动作，是把一条便签投递成一张 Markdown 想法卡。这份文档写清楚卡片长什么样、为什么这样、以及读的人应该怎么用。

**写的人负责格式，读的人保持简单。** 不要指望消费端做兼容补丁。

## 触发条件

只有人点 **投到灵感**（或显式让模型调 `note_promote`）才会写。便签正文永远不会自动进库。

- 唯一写路径：`POST /api/scratchpad/notes/:id/promote`
- 一次投递只写一张卡
- 失败只报错，**不自动重试**——重试会产出 `-2` 重复卡

## 落地位置

```
<库根>/00-收件箱/想法-<yyyymmdd-HHmm>-<6位随机>.md
```

`<库根>` 从 `~/.dsh/lingtai/settings.json` 的 `root` 读，缺省 Windows `C:\Creator`、其他系统 `~/Creator`。**调用方不能指定路径。**

文件名用紧凑时间戳而不是「日期_状态_标题」，是为了避免标题里的非法字符和重名；信息都在 frontmatter 里，读的人不需要解析文件名。

## 卡片格式

```markdown
---
状态: 想法
平台: 全平台 | 抖音 | 小红书
主题: <便签首行，净化后截 40 字>
创建: <便签产生日 YYYY-MM-DD>
更新: <投递日 YYYY-MM-DD>
星位: 天枢
type: idea
source: 速记便签
note_id: <便签 id>
created: <YYYY-MM-DD HH:mm>
platform: <同上>
---

> 来源：速记便签 <note_id> · <便签产生时间 YYYY-MM-DD HH:mm>

<便签原文，不改写>
```

### 六个中文键

| 键 | 取值 | 为什么 |
| --- | --- | --- |
| `状态` | 固定 `想法` | 消费端用它分流「想法 / 选题 / 脚本」 |
| `平台` | `全平台` / `抖音` / `小红书` | 用户在投递对话框里选；越界值回退 `全平台` |
| `主题` | 便签首个非空行，净化后截 40 字 | 标题的唯一来源；没有它消费端只能退回文件名 |
| `创建` | 便签产生那天（`YYYY-MM-DD`） | 保留想法的诞生日 |
| `更新` | 投递那天（`YYYY-MM-DD`） | 消费端按「更新」倒序 = 按投递时间排 |
| `星位` | 固定 `天枢` | 上游知识库的位置约定 |

### 英文小写键

`type` / `source` / `note_id` / `created` / `platform` 是 v1.7 的兼容位。旧卡片和旧读取器还在依赖它们，**不要删**。新键只增不改。

## 标题净化

`: # [ ] { } > | * ? " < > !`、行首 `-` 会被替换成空格，连续空白压成一个，截 40 字。原文本身**不改写**——净化只作用于 `主题` 字段。

## 读者应该怎么用

1. 先读 frontmatter 的 `状态` 决定归类，不要从文件名猜。
2. 标题读 `主题`；取不到再退回正文第一个标题、第一行、最后才是文件名。
3. 排序按 `更新` 倒序；不要用文件 mtime（跨天会差一天）。
4. 正文第一行是 `>` 引用形式的来源标注，正文原文在其后。要展示原文就跳过引用块。

## 改这份契约的成本

`buildIdeaMarkdown`（`index.js`）是唯一的生成点，`tests/storage.test.mjs` 断言了字段集合与取值。改字段必须同时改三处：生成函数、`docs/IDEA-CONTRACT.md`（本文）、以及测试断言。少改一处，测试会红或者读取方会静默退化。
